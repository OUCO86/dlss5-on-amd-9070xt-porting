# 真正的720p网络计算实验

开发分支：`720p`，从`main`的`85feab0`分出。正式0.15安装、包、tag与main不变。

`DLSS5_NETWORK_720P=1`选择网络有效1280×720、处理1280×768；默认0仍为1920×1080/1920×1152。外部窗口仍可到1920×1080，codec按网络实际尺寸进行适配并还原外部尺寸。它与`DLSS5_FIT_INPUT`不同：后者只允许较小窗口接入，不改变网络计算尺寸。

720路径的空间网格：1280×768 → 640×384 → 320×192 → 160×96 → 80×48 → 40×24 → 20×12；ViT使用240个真实token，不用虚拟token补到256。原1080路径的head保持32×20、640token。权重与跳块策略不变。

## 2026-09-13测试结果

RX9070XT，独立D3D12测试台，同一套发布flags，固定合成梯度/棋盘输入，零运动向量、时序开启；每次恢复原输入再计时，3帧预热后测60帧。GPU队列时间覆盖encode、时序、网络、decode及提交间隙，不含恢复输入、初始化、游戏、Magpie捕获、FSR4、帧生成。

| 内部计算 | 平均GPU时间 | 中位GPU时间 | 最短GPU时间 | 平均对应FPS | 最短帧对应FPS |
|---|---:|---:|---:|---:|---:|
| 1080p | 22.010ms | 21.994ms | 21.821ms | 45.43 | 45.83 |
| 720p | 10.934ms | 10.894ms | 10.815ms | 91.46 | 92.47 |

CPU墙钟平均1080p22.178ms、720p11.107ms。720p约2倍吞吐。最短帧是本次观测值，不是硬件的绝对上限。实际游戏帧率和画质尚未验收，不能把这些数写成游戏FPS。

验证：C++插件/测试台交叉编译通过；207个预编译shader通过；几何与视口测试通过；64/640 token的生成映射与捕获文件逐项一致，240映射双射；720p历史3,686,400个float与1080p历史8,294,400个float均无NaN/Inf。修正后的输出图已查看，保留预期梯度和棋盘结构。各尺寸图像内容的采样频率不同，没有据此计算跨分辨率PSNR。

## 本次修过的坑

- ViT240不是64的倍数，QKV用新m1核；attention最后16个key需要mask，V最后半块补零，不能读到下一个head/plane。
- m1 expand旧代码漏了tiled布局：A/B按普通行读，hidden按普通行写，后继却按tile读。初次720输出明显变暗、有噪点（RGB均值70.9，初测11.25ms）；这份结果作废。补齐3处tile地址后均值127.9，速度10.93ms。不能把finite或出图当成正确。
- 所有尺寸相关边界都要改：输入镜像补边、RGB桥接、历史buffer和feed、视口、运动坐标、decoder投影、ViT映射与尾块。仅删除1080检查不够。
- 远端D盘不支持这次使用的hardlink接口，资产准备自动回退普通复制；只建立一份隔离测试资产，未写回正式资产。
