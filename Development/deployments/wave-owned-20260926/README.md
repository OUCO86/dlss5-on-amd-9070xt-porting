# Wave-owned opt-in production candidate

`DLSS5_HIP_WAVE_OWNED=1` uses the validated 46-block path in the NativeGameFrame add-on. Default 0 retains prod8. Only compatible packed/byte-stream layouts activate it; incompatible layouts, graph capture or skips in the replaced ranges fall back. ViT skips 42/43/46 remain supported. Missing new modules on a compatible enabled configuration are a load error, not a silent partial activation. RE9/standalone C API configuration is a separate follow-up; this candidate targets the Magpie/regular OptiScaler add-on.

Canonical kernels are `hip/wave_owned_*.inc`; experiment generators read these same files. Standard `hip/build-modules.ps1` now builds 26 modules. `Development/HIP/prepare_wave_owned.py` emits just the two additional modules for incremental builds. `build.ps1` builds both gfx1200 and gfx1201. `verify-recipe.ps1` checks standard and incremental recipes' complete assembly/metadata after normalizing only the compiler-generated `__hip_cuid_<hex>` symbol; resulting module files may have different hashes.

The actual production host is compiled from `Development/HIP/benchmark_vit_reuse.cpp`. `prepare-trace.py` makes a diagnostic copy adding dispatch counters only; correctness tests use it, performance uses the unmodified production host. `regression.ps1` checks static/motion/history on 720/900/1080, plus two fallback layouts using the old module directory (without either extra module). `collect.ps1` and `analyze.py` archive/validate outputs and timing. Results are in `Development/results/wave-owned-production-20260926`.

The add-on is built with `scripts/build-addon.sh ... --hip`. `prepare-payload.ps1` stages four new architecture-specific modules plus the add-on; it does not install them. The laboratory gfx1200 baseline is incremental (five updated modules), whereas gfx1201 has all 24 legacy modules. The payload only adds the new pair per architecture. The baseline manifest checks all hashes available from those lab sets; other installed legacy files are not replaced.

`install.ps1` is prepared for Stellar Blade/Cyberpunk, but has not been executed. It requires the game to be closed, checks known prod8 hashes and the installed add-on, rejects an external module-directory override, saves old files/flags with hashes, installs the payload, sets only the new flag and verifies host/INI preservation. `-RestoreBackup <directory>` restores prior files and removes newly added modules. Next: capture a same-scene game baseline, then test the candidate with rollback available. No public release or game installation has been changed by this work.
