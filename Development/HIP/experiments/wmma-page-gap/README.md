# 算力缺口：固定高位地址的块内异或

接续pitch对照，排查“改变访问页/页足迹”与“页内地址分布/访问顺序”的混杂。不是生产优化。

原N16权重tile仍间隔16384字节。将tile内地址off替换为off XOR ((tile*256)&mix)，mix只使用bit8～11（256/512/768/1024/2048/3072/3840）。每次8字节加载仍连续对齐、低8位不变；基址要求4KiB对齐，逐访问的地址高位addr>>12保持不变。A、循环、矩阵/加载数量不变。

span64中mix<1024仅重排原1KiB内地址，精确地址集合也不变；mix>=1024可能移动到同一4KiB内其他位置，但不同元素数与高位序列仍不变。span1024遍历整个tile，任何mix都只是置换，精确地址集合始终相同。CPU穷举脚本address-check.py验证对齐、无碰撞、不同字节数及高位不变，不能据此假定GPU真实页大小或cache银行结构。

假说：若保持高位地址乃至精确地址集合后慢点仍能改变，则“访问了不同页/工作集容量不同”不足以解释；更需查请求时序、地址低位映射及服务分布。若效果消失，再回查上轮pitch带来的高位/页足迹变化。

先校准pitched4和xor4在mix0时的编译/寄存器扰动；正式只在同一个xor4入口改mix。保留span1024完整权重对照，避免只解释特殊span64慢点。沿用计时外显存搬运、分chunk及只读ADL，不改GPU时钟设置。所有结果为合成1/16校验和诊断，不是原网络输出或实际优化。

本轮完成：128槽1341200次计时launch、256次全lane校验和通过；三次RGP各64dispatch/各三次checksum通过，无捕获控制三次通过。span64的bit10敏感性在高位不变下仍存在，完整span1024无大幅收益。bit11捕获停顿与独立wall不一致，保留不同捕获状态的限制，不以计数器百分比分账。

request-account.py将上一轮真实原核的262144000次L0请求及合成核251822080次请求逐项算回；128B区域覆盖不等于真实传输字节。官方口径与下一步见[报告](../../../results/wmma-page-gap-20260922/README.md)。后续优先在完整权重上区分请求宽度/发射/服务能力，暂停追特殊小集合地址技巧。
