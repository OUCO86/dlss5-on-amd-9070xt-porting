# 当前 C32 阶段采样（prod8，2026-09-25）

旧 c32-phase-trace 每核前同步并复制模块全局指针；本工具在实验 host 中预分配约 10MiB trace 缓冲，指针和采样偏移作为尾部核参数传入，不在 launch 之间同步/读回。保留所有生产导出，新增 `_phaseN` 孪生。

每次只记录一个阶段和整段的时间差，使用 `s_getreg_b32 hwreg(29,0,20)` 本地20位 SHADER_CYCLES。差值按模 2^20 计算，不使用 `s_sendmsg_rtn REALTIME`，不额外插入设备等待来清空管线。所得是指令边界之间的观测区间，未完成的访存/计算可能由后面的原有等待承担。

每32个窗口抽一个窗口，四个 wave 的 lane0各写四个 uint：阶段周期、整段周期、窗口编号、magic/phase。每个阶段独立保存8帧；最新版偏移 `(frame*5)%32`，覆盖不同低位余数。第一轮粗分用 `frame*4`，分析时传4，已明确保留区别。全体 wave 执行少量计时指令，只有采样 wave 写出；这不是零扰动采样。

| phase | 区间 |
|---|---|
| 0 | 整段（入口至尾部完成，写 trace 前） |
| 1 | 输入准备；prefix 核包含输入/噪声生成和 prefix 投影 |
| 2 | 入口同步 + 残差初始化 + FFN 展开/收缩 + FFN 结果发布 |
| 3 | QKV 与归一化 |
| 4 | 注意力分数、概率、AV 与发布 |
| 5 | 投影/原输出路径 |
| 6 | Finish 或 RGB head；无尾部的核用作空区间对照 |
| 7 | FFN 入口的原同步 |
| 8 | FFN 残差初始化 |
| 9 | FFN 展开、激活、收缩主体 |
| 10 | FFN 结果转换、LDS 写出与原同步 |

执行：prepare.py → MinGW 编译 network.cpp → 传到靶机 → start.ps1。脚本自主检查空闲，实验模块只从 prod8 复制，绝不覆盖游戏。

每个阶段先正常/插桩/插桩/正常四槽，每槽预热20、计时80帧，计时外 RGB 逐位检查；再保存8帧并逐帧核对 RGB。`-Phases 0,1,2,7,8,9,10 -Label ffn` 跑 FFN 细分。`analyze.py <目录> [采样步长，默认5]` 验证每条记录和样本数，输出逐 launch/逐帧摘要。

`inspect.py <prod8.hsaco> <实验.hsaco> <实验.s>` 核对原核机器码未变、计时指令、VGPR/SGPR/溢出。`MSG_DEALLOC_VGPRS` 是寄存器释放，不是 REALTIME 计时消息，不应误报。

解释边界：插桩仍会改变寄存器与调度；各阶段是分开编译的，不能把它们相加强行归一，也不能把 wave 周期占比当整网墙钟份额。先看扰动，再看两档和两种采样余数是否支持同一个热点排序。
