# 真实网络中重复pack+expand，放大wall差异

沿用上一轮32×64/片段A/u2与生产核。每个ViT块首次pack/expand照常执行，额外重复0/1/3次相同pack+expand，覆盖同一输出；输入/权重/累加顺序与最终输出不变。保存pack参数值和函数句柄，显式核对与随后expand的输入一致。仅新增kernel dispatch，不插GPU事件或段内CPU同步。

五组各两轮ABBA：R1/R2/R4下原核对候选、原核R1对R4、候选R1对R4。每槽30预热/120计时，逐槽完整FP32与黄金对照，检查原pair/extra pair/expand/替换数。只读ADL、GPU空闲守卫、先1080后900。实验host使用既有双架构编译的vit-eight-accumulators/modules-u2，实跑gfx1201，不改生产或游戏。

多做计算是诊断，不是优化。wall增量包括CPU提交、缓存重用、GPU调度和状态变化；不直接将斜率当第一次真实算子的独立耗时。

补充控制：
- 集中与分散：保持额外24对pack+expand不变，对比每层额外3对与仅block31额外24对；不是冷热首次执行次数对照，两者仍各有8个首次执行。
- 权重地址：每个展开权重复制3份（共96MiB），共享与独立地址两边都预先分配相同副本；只有额外3次展开使用原指针或副本指针，值/shape/dispatch数量相同。最终host两边走相同CPU指针查找路径；初版仅独立地址侧查询的pilot保留、不作主要依据。该对照改变跨调用权重局部性，也可能影响cache映射/其他层，不直接称DRAM冷读。
