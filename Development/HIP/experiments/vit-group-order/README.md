# ViT 展开核：局部二维任务编号（2026-09-25，Yami）

## 要回答的问题

真实 `vit_expand_blocked_fp8_frag_bytein` 每组一个 wave，产出 16 token × 64 列。原编号先走完一行 token tile 的 64 个列 tile，再换下一行，优先复用 A。候选每次取 2/4/8 行 token tile，在它们之间先走同一列 tile，让 B 权重的复用时间更接近。

例如 GM=2：原来 `(m0,n0),(m0,n1),…,(m1,n0)`，改为 `(m0,n0),(m1,n0),(m0,n1),(m1,n1),…`。数学任务、输出地址、每组线程数、每个累加器的 K 顺序不变。工作组编号不保证等于物理执行顺序。

这区别于旧 wmma-groups-gap 的随机乘 stride 置换、多 wave 合组。本次直接在真实核/真实整网中测，保持原工作组大小，不继续追 span64 的特殊地址冲突。灵感来自 PR #2217 的工作集复用思想，不搬它的按头拆 launch，也不预设倍数收益。

## 变体

| mode | 内容 |
|---|---|
| 0 | 原生产核 |
| 1 | 同代码异名 control |
| 2 | GM=2 |
| 3 | GM=4 |
| 4 | GM=8 |
| 5 | 只改收缩核 GM=2 |
| 6 | 只改收缩核 GM=4 |
| 7 | 只改收缩核 GM=8 |

mode 2～4 只改展开核。收缩核每行只有 16 个列 tile，同一工作量下的局部工作集不同，所以独立对照 mode 5～7。第二轮 control 同时给展开/收缩使用同体异名导出；每帧统计目标调用总数 16（第一轮只统计展开的 8 次，CSV 字段保留区别）。

900 档 400 token = 25 行 tile，最后一组必须按真实剩余行数映射；1080 档 640 token = 40 行。`check-mapping.py` 穷举代表性完整/残组网格，验证无漏无重。

## 测量

- `prepare.py` 从生产 deep_fast.hip 生成新导出和 host 副本，复用 c32-post-input 的 ABBA runner 模板，计数确认展开/收缩都实际执行。
- `build.ps1` 从 prod8 复制独立模块集，仅替换 deep_fast-packed；保留全部生产导出。`inspect.py` 比对全部原核的 ELF 函数体，确认 control 也逐字节相同。
- 两档整网，PDL=1，adaptive/graph/dup 关；每候选三组 ABBA，每槽预热20、计时160帧，只在计时外核对 RGB 槽首尾。另核对目标调用次数，防止替换没命中。
- 几何映射只涉及整数，但额外地址计算可能改变编译器调度，资源表和机器码仍须检查。不把候选耗时差直接归给缓存。
- `start.ps1` 自主检查空闲、编译、跑实验；`run.ps1 -Candidates 1,3 -Label repeat` 可限定复测。绝不覆盖游戏文件。
- 固定输入筛选通过且有稳定收益，才做多帧历史回归、双架构和生产化。
