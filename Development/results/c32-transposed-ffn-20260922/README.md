# C32 折叠 FFN：展开→收缩不走 LDS（2026-09-22，Hikari）

起点：C32 发射预算里 LDS 管线约 0.26ms，其中 FFN 展开把激活后的 hidden 块按字节写进 `scratch.hidden`（每 wave 64 条 ds_store_b8），收缩再按字节读回，中间隔一个工作组同步。这个往返只为把上一个矩阵的输出转置成下一个矩阵的输入。

**机制**：gfx12 WMMA 的 A、B 操作数寄存器格式相同（lane%16 = M 或 N 下标，lane/16 选 k 半段）。把展开的两个操作数对调，得到的是 D^T：每个 lane 持有一行、8 个连续 hidden 列，正好是收缩所需的 A 片段。激活后在寄存器里打包成 FP8，直接喂收缩，hidden 不进 LDS。累加器的残差初始化挪到展开循环前，保持"先残差、后收缩累加"的原顺序。

## 三轮

**第 1 轮**（弃）：`i2 hfrag[8]` 数组先存 8 个 tile 再收缩。逐位同，但运行时下标迫使编译器全展开（post 静态指令 2999→3779，WMMA 58→72，VALU +650 全是展开副本），整网反而 +0.05～0.2ms。r1 计时目录在远端被覆盖，数值仅存对话记录：1080 +0.07/+0.20/+0.15，900 +0.05/+0.15/+0.11（pair1/2/3）。

**第 2、3 轮**（两轮独立复现）：

| 变体 | 内容 |
|---|---|
| pair1 | 收缩折进展开循环（每 tile：2 条展开 WMMA → 激活打包 → 2 条收缩 WMMA），循环保持卷起，两处 FFN 同步保留 |
| pair2 | 对照：原 LDS 路径，仅把展开循环强制全展开（只看代码体积/调度效应） |
| pair3 | pair1 + 去掉展开与收缩之间的同步（hidden 已不在 LDS，其间无其他 LDS 访问） |

ISA（post 核）：原版 2999 指令 / 58 WMMA / 417 LDS 指令；pair1 2997 / 44 / 401（静态 WMMA 少是收缩进了卷起的循环）；pair3 再少一个 barrier；pair2 3731 指令、VGPR 158→148。

整网 ABBA（每槽 160 帧、每测试 8 槽，原始 FP32 逐位同、替换 1600/槽）：

| 轮 | 档 | pair1 折叠 | pair2 仅展开 | pair3 折叠+去同步 |
|---|---|---:|---:|---:|
| 2 | 1080 | −0.104（交叠） | −0.073 | −0.093 |
| 2 | 900 | −0.053 | −0.028（交叠） | −0.045 |
| 3 | 1080 | −0.104 | −0.063（交叠） | −0.110 |
| 3 | 900 | −0.063 | −0.039 | −0.059 |

核心频率两侧相同（±5MHz），显存 2505。折叠版两轮一致 −0.10 / −0.06 ms（约整网 −0.6% / −0.5%），比栅栏那笔小，但机制单一、逐位同。单纯展开的对照组只有一半且不稳定，说明收益主要来自去掉 LDS 往返，不是代码布局。

## 采用

pair3 进生产源码 `hip/c32_fused_ffn_attention.hip`，开关 `HIP_C32_FOLDED_FFN`（默认 1）。生产构建 10 核与实验 pair3 机器码逐条相同（分支标签归一化后）。正式回归见 deployments/stellar-prod2-20260922。
