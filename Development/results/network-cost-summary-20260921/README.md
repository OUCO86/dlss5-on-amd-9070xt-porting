截至 2026-09-21 22时这批，计划中的 C32 主干/输入/尾部和 ViT FFN 真实尺寸台阶已完成。这里汇总已支持的判断；中间其他通道层没有全部细拆。

## 现在的解释

显卡的矩阵计算峰值确实能达到。网络的主矩阵FLOPs除整网时间只有约55TF，是把读取、转换、归一化、残差、同步和输出都放进同一个分母后的有效吞吐，不能据此说硬件只用了七分之一、还可直接提速七倍。

目前看到的是两类不同缺口：C32是许多小矩阵与大量辅助工作融合在一起，实际汇编已经有双发射；ViT大矩阵即使去掉激活/最终编码，仍不能靠现有访存/调度方式接近寄存器峰值。二者需要不同的优化方向，尚未发现一个解释全部耗时的统一开关。

C32输入和尾部并非零成本，重复实验已能观察到增量；但输入探针包含额外同步，部分探针改变寄存器和调度，RGB重复还呈现非线性。因此这些数字只适合筛选调查方向，不画成加起来100%的阶段饼图。

FFN展开在900去掉尾部能少约3.6μs，1080基本持平；补成等价拆分流程却分别多约3.8/13.3μs。收缩去掉末端舍入只差约0.3/0.6μs，拆分也更慢。展开FP32中间输出增大四倍，不能把这些差值说成纯激活耗时，但足够否定“先把尾部拆出去就会快”的这次候选。

## 下一步优先级

1. 在真实ViT展开核上做加载/矩阵调度的受控对照：保留布局、tile、K顺序和输出，分别改变A/B片段提前读取与流水组织；先验证是否能缩小裸矩阵缺口。同步记录寄存器资源和实际时钟。
2. C32只挑一个明确的数据往返改动做等价候选，按真实整网收益验收；输入合并/格式暂存有成本，但不要重做已经更慢的“删掉post half暂存、残差重读”方案。
3. 更深入硬件计数器只用输出已验证的纯HIP路径；之前混合D3D/HIP捕获输出错误的数据继续弃用。现有证据不足以给出DRAM、LDS、指令依赖各自的精确时间比例。

本次新增两组实验共200个计时槽、20次整网原始FP32检查通过；双架构编译，实跑gfx1201。没有新增已采用的生产优化。原始报告继续保留，以上结论不替代各报告的测量限制。

## 22:33后补充：ViT展开/收缩的不对称已有因果证据

[正反对照实验](../vit-schedule-cause-20260921/README.md)：展开传编译期K1024/N4096，让编译器自动四份展开，1080从56.2降至36.2μs；固定尺寸却禁止展开仅约4%改善，动态尺寸只写unroll提示没有改变机器码或速度。反向取消收缩的展开则从36.1升至76.7μs。运算顺序与输出全同，支持循环展开后的读取/地址/指令调度是这对算子差异的主要来源。整网正向900/1080省0.087/0.206ms，观测频率没有升高。此结论不覆盖整网全部差距，也没有给显存等待做精确占比；研究候选尚未部署。

## 22:51后补充：全网筛选后采用三项无损改动

[八组候选与正式回归](../network-fixed-shapes-20260921/README.md)：审计默认路径234调用，分别试固定通道/尺寸/token。采用ViT展开、ViT投影、解码器投影；其余候选收益小或两档不一致，保留实验。正常ABI模块千帧ABBA：900省0.159690ms（1.21%），1080省0.310209ms（1.67%）；96对逐帧RGB及最终模块四次原始FP32输出全同。主线hip/deep_fast.hip已更新，固定的是通道维度，图像宽高仍动态，未改变画质配置。先前报告中的基线已成为本次改动前的历史测量，后续实验请以本次selected-modules为新基线。

## 23:15研究主线校准：算力缺口是核心验证器

用户明确：研究的核心始终是解释算力缺口，提速是结果之一，不能用“又省了几微秒”替代机制认识。

后续每轮记录四件事：当前比较口径与缺口、待验证的具体原因、能区分这些原因的对照、实验后已解释与仍未解释的部分。负优化若能排除一个原因，同样是有效研究；正优化只有耗时变化、没有机制证据，也不能宣布缺口已解释。

近期聚焦改善后的ViT展开：真实尺寸有效吞吐约148TF，与约405TF寄存器峰值之间还有差距。二者的访存和工作条件不同，这个差值是研究问题，不是已经证明可追回的闲置算力。优先控制数据读取/复用、循环调度与并行工作规模，配对记录时钟、输出一致性和生成指令，逐步区分原因。整网收益继续作为工程验收；算力缺口解释作为研究验收。
