截至 2026-09-21 22时这批，计划中的 C32 主干/输入/尾部和 ViT FFN 真实尺寸台阶已完成。这里汇总已支持的判断；中间其他通道层没有全部细拆。

## 现在的解释

显卡的矩阵计算峰值确实能达到。网络的主矩阵FLOPs除整网时间只有约55TF，是把读取、转换、归一化、残差、同步和输出都放进同一个分母后的有效吞吐，不能据此说硬件只用了七分之一、还可直接提速七倍。

目前看到的是两类不同缺口：C32是许多小矩阵与大量辅助工作融合在一起，实际汇编已经有双发射；ViT大矩阵即使去掉激活/最终编码，仍不能靠现有访存/调度方式接近寄存器峰值。二者需要不同的优化方向，尚未发现一个解释全部耗时的统一开关。

C32输入和尾部并非零成本，重复实验已能观察到增量；但输入探针包含额外同步，部分探针改变寄存器和调度，RGB重复还呈现非线性。因此这些数字只适合筛选调查方向，不画成加起来100%的阶段饼图。

FFN展开在900去掉尾部能少约3.6μs，1080基本持平；补成等价拆分流程却分别多约3.8/13.3μs。收缩去掉末端舍入只差约0.3/0.6μs，拆分也更慢。展开FP32中间输出增大四倍，不能把这些差值说成纯激活耗时，但足够否定“先把尾部拆出去就会快”的这次候选。

## 下一步优先级

1. 在真实ViT展开核上做加载/矩阵调度的受控对照：保留布局、tile、K顺序和输出，分别改变A/B片段提前读取与流水组织；先验证是否能缩小裸矩阵缺口。同步记录寄存器资源和实际时钟。
2. C32只挑一个明确的数据往返改动做等价候选，按真实整网收益验收；输入合并/格式暂存有成本，但不要重做已经更慢的“删掉post half暂存、残差重读”方案。
3. 更深入硬件计数器只用输出已验证的纯HIP路径；之前混合D3D/HIP捕获输出错误的数据继续弃用。现有证据不足以给出DRAM、LDS、指令依赖各自的精确时间比例。

本次新增两组实验共200个计时槽、20次整网原始FP32检查通过；双架构编译，实跑gfx1201。没有新增已采用的生产优化。原始报告继续保留，以上结论不替代各报告的测量限制。
