# ViT 展开/收缩不对称：固定尺寸与循环展开的因果对照

基线 ab3e209（GPU源固定8bca0f7，期间生产源未变）。选ViT FFN展开/收缩，因为两者主矩阵FLOPs相同，而1080完整展开约57μs、收缩约36μs。C32的约35%耗时仍是更大的整网热点，但与寄存器峰值比较混入很多非矩阵工作，不如这对算子适合先解释机制。

## 对照结果

真实block31输入/权重，原16×64输出tile、矩阵K累加顺序、精度、激活和输出布局全部保留。每项两轮ABBA，host wall+sync批计时。

| 改动 | 900 原核→候选 μs | 1080 原核→候选 μs |
|---|---:|---:|
| 展开：传编译期常量K1024/N4096，允许自动优化 | 32.771→24.157（-26.29%） | 56.185→36.181（-35.60%） |
| 展开：同样固定尺寸，但禁止K循环展开 | 32.781→31.701（-3.29%） | 56.610→54.301（-4.08%） |
| 展开：仍用运行时尺寸，仅加unroll4提示 | 32.939→32.892（-0.14%） | 56.821→56.907（+0.15%） |
| 展开：固定尺寸，显式unroll4 | 32.950→24.263（-26.36%） | 56.823→36.210（-36.28%） |
| 收缩：禁止K循环展开 | 24.529→67.375（+174.68%） | 36.106→76.682（+112.38%） |

固定尺寸后，展开与原收缩的时间已接近。反向干预同样使收缩大幅变慢，足以把这一对算子的主要差距定位到编译后的循环/读取调度，不能仅归因“展开激活更贵”。

## 汇编对应的机制

原展开每轮K16：5条global_load_b64（1份A、4份B），4条WMMA、4处wait_loadcnt，然后循环分支。运行64轮。

固定尺寸后编译器自动四份展开：每轮K64提前发出20条load，之后16条WMMA，共4处wait_loadcnt。运行16轮。矩阵运算次数和主输入/权重读取字节数相同，但工作可以提前安排，地址计算也大量变成固定偏移。VGPR47→77，LDS0、scratch0、编译器Occupancy16均不变。

这里是循环展开，不是四倍矩阵工作或四倍独立累加器：每个结果仍按原K顺序累加。wait指令减少也不等于等待时间按比例减少；它是生成代码的证据，实际提速由对照测量给出。

固定尺寸但不展开只有约3～4%改善，表明常量寻址/边界简化不是全部。运行时尺寸只加unroll4提示，实际仍只有4条静态WMMA，速度也没变：写了pragma不代表编译器做到了。收缩原来各K1024分段内已四份展开，禁止后VGPR205→175、Occupancy7→8，反而明显更慢，再次说明低寄存器不自动等于高性能。

每算子的主循环逻辑加载量，M400约125MiB、M640约200MiB；按每wave的8字节×32lane×load次数计算，两者相同。主输出写出字节也相同：展开M×4096个FP8，收缩M×1024个FP32。收缩另有残差读取；缓存重用方式不同。**逻辑加载不是DRAM流量**，不能把上述字节除时间当显存带宽；此次没有测出缓存层级或等待原因的周期占比。

## 整网闭环

只在实验host切换导出，每帧替换8次目标调用，其余路径不变。每档两方案各8槽，40帧预热+100帧计时/槽；逐槽检查完整原始FP32输出。Graph/复用关，固定真实画面。

| 方案 | 900整网 ms | 1080整网 ms |
|---|---:|---:|
| 仅展开固定尺寸 | 12.849280→12.762520，省0.086760（0.68%） | 18.290058→18.084005，省0.206053（1.13%） |
| 仅收缩禁止展开（反向诊断） | 12.901725→13.324723，多0.422998 | 18.362263→18.797058，多0.434795 |

只读ADL配对遥测：正向整网900核心中位2771→2765.5MHz，1080为2727→2721MHz；提速没有伴随更高观测核心频率。单核正向候选的采样时钟同样较低，反向候选较高却更慢。200ms粗采样，不据此计算精确周期利用率或因果频率模型；没有改任何频率/功耗设置。

## 可以学到什么

这一次不一致有了可复现的解释：通用尺寸参数让编译器生成短循环，数据准备、地址计算与矩阵指令交错方式限制了吞吐；常量尺寸解锁四份展开，允许更大范围的读取/计算调度。它证实了此处的组织方式很重要，但尚未拆分出访存延迟、地址指令、循环控制分别省多少，也没证明显存带宽饱和。

局部展开快约26～36%，整网只省约0.7～1.1%，因为仅影响每帧8个算子。改后仍只有约139/148TF主矩阵有效吞吐，剩余与405TF寄存器峰值的差距尚待解释。

下一步可在这份已固定尺寸的核上比较有限展开因子与读取组织，判断工作提前安排到什么程度开始受寄存器/缓存限制；不要直接在所有算子强制展开。

## 验证与工件

五种变体，80个单核计时槽完整输出相同，8次首尾整网FP32相同；整网额外32槽共3200计时帧，32次批末FP32逐位同，每候选槽确认800次替换。双架构编译，实跑仅gfx1201。源码、脚本在experiments/vit-schedule-cause；CSV/遥测/hash/isa/summary均在此目录。关键循环汇编片段在isa-loops/，静态指令数不作时间占比。
