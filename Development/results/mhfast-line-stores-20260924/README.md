# FFN+QKV 尾段全行写（HIP_FFN_LINE_STORES）——逐位同，−0.6/−0.7%（2026-09-24 01:25，Hikari）

来源：频率账本（`clock-ledger-20260924`）把 FFN 核族的电烧追到全局窄写：转置尾段虽然把 norm 写从每 lane 24 条 b8 并成 3 条 b64，但 lane = 行，每条写指令仍触及 16 条缓存行，功耗一点没降；去掉 norm 写 +4% 时钟、norm 和 out 都去 +7%。

改法（`hip/multihead_fast_padded.hip`，`mh_ffn_qkv_body` 转置尾段、非 BatchNorm、ByteFeature 分支）：
- out：字节本来就写进了 qfeature（16 行 × (C+4) 的 LDS 暂存），后面本有一个 barrier。去掉循环里的 out 全局写，barrier 之后全组从 qfeature 按 8 字节/线程写出——2C 个线程正好 16 行 × C/8 片，C=256 时一个 wave 写一整行 256 B 连续 = 两条整行，每行只写一次。
- norm：三个 part 的字节先暂存到 LDS（part 0/1 共用一块、part 2 一块，行距 C+8 让 16 个 lane 落不同 bank），part 0 在 part 1 的第一个 barrier 之后整行写出（不加 barrier），part 1/2 在结尾多一个 barrier（WG_FENCE 3/2 + s_barrier）后写出。
- 同字节同地址：逐位。LDS 每组 +2×16×(C+8)：C256 21,568→30,016 B，驻留仍由 VGPR 定在 12 wave/SIMD（VGPR 97→98）；C64/C128 同理。开关默认 0，生产体 ISA 与 prod6 零差异。

多了一个 barrier 和两块 LDS 往返还净赚，说明请求数（触及行 × 部分写）确实是这段的成本主项——和 318 那条"读写成本 = 指令数 + 触及行数"以及功耗账一致。
