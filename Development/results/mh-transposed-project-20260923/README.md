# 注意力投影输出转置（WMMA 操作数对调），逐位同，反而 +0.05～+0.16ms，不采用（2026-09-23，Hikari）

想把 ffn_fused 那刀（[尾段转置](../mhfast-transposed-qkv-20260923/README.md)，−1.7%）搬到 mh_fused 三个注意力核的投影输出：残差对角 WMMA 与 AV×W 投影 WMMA 操作数对调，lane 持一个 token 行、8 个连续输出列，裁剪判断每 lane 一次，字节输出 8 个连续。pair1 只改 c256，pair2 三核，pair3 = pair1。逐位同（bitdiff 0）。

| 档 | pair1 c256 | pair2 三核 | pair3 c256 |
|---|---:|---:|---:|
| 1080 | +0.121 | +0.162 | +0.091 ms |
| 900 | +0.061 | +0.105 | +0.050 ms |

槽全部不交叠、核心频率两侧相同。

ISA 说明了为什么：

| 核 | 指令 | 全局写 | SALU | VGPR |
|---|---:|---:|---:|---:|
| c256 原版 → 转置 | 1818 → 2193 | 2 → 8 | 531 → 790 | **118 → 138** |
| c128 | 1495 → 1807 | 2 → 8 | 434 → 642 | 92 → 91 |
| c64 | 1445 → 1742 | 2 → 8 | 410 → 608 | 92 → 92 |

原版的输出循环是**运行时滚动循环**（裁剪 `continue` 让编译器没展开，静态只有 2 条全局写），每元素一次地址计算；转置后编译器把 8 列展开成 8 条写加各自的地址算术，指令多 20%，c256 还多 20 个 VGPR（12→10 wave/SIMD，3→2 组/WGP）。ffn_fused 那边原版就是展开的 24 条字节写，转置把它并成 3 条；这边原版本来就只有 2 条，转置是往回走。

规则再补一句：**转置并宽的收益取决于原版是不是"展开的多条窄写"；原版是滚动循环时先别动。** 此线关闭。

证据：1080/、900/ 下 network.csv、run.log、telemetry.log；summary.txt；console.log。工具 HIP/experiments/mh-transposed-project。
