# ffn_fused_c256 宽权重片段（8B→16B 读，2026-09-23，Hikari）

打点账里该核每 wave 162 条全局读，其中约 136 条是 `frag_b` 的 8 字节权重片段（每条 WMMA 一条）。片段打包布局里同一 lane 的两个 K16 片段相隔 256 字节，不能并读。改打包：512 字节 tile 内按 [lane 半 gr][row%16][K16 序][8 字节] 排，同一 lane 的两个 K16 片段相邻，一条 16 字节读喂两条 WMMA。核里展开/收缩/投影/QKV 四个循环步长 16→32，累加顺序不变（k 升序）。同字节、同顺序 → 逐位同。

实现：host 复制两个打包器（`@ffn-frag-wide`、`@qkv-frag-only-wide`，只有 c256 frag 核消费这两个键），pair 模式下 c256 launch 换用宽缓冲；模块集 pair1 = 宽核（pair2/3 复制）。

ISA：global_load 162→94（b128 68 条），指令 2237→2105，WMMA、barrier、VGPR、驻留不变。

整网 ABBA 两轮（每测试 8 槽 160 帧，逐位同）：

| 轮 | 档 | rep1 | rep2 | rep3 |
|---|---|---:|---:|---:|
| r1 | 1080 | −0.189* | −0.039 | −0.052 |
| r1 | 900 | −0.149* | −0.009 | −0.023 |
| r2 | 1080 | −0.174* | −0.036 | −0.030 |
| r2 | 900 | −0.148* | −0.026 | −0.032 |

\* rep1 含进程首个对照槽（冷启动 17.44/12.63，其余槽 17.0/12.1），剔除后与 rep2/3 一致。**收益约 −0.03～−0.04ms（0.25%）**，900 槽间分开。

结论：权重读请求减半只换来 0.25%——这个核的瓶颈不在权重读，与打点账（尾段 43%、barrier 19%）一致。**未采用**：打包器是 host 代码，编在 addon DLL 与回归 exe 里，采用要重编 addon 并换 DLL，代价与收益不配；下次因别的原因重编 addon 时可顺带带上（核改动加开关即可，打包器改两处函数）。

证据：r1/、r2/。工具 HIP/experiments/mhfast-wide-frag（prepare.py 同时生成宽打包 host 与核）。
