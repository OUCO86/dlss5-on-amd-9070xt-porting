# C32 转置尾部（HIP_C32_TRANSPOSED_TAIL）——逐位同，慢 0.03ms，关闭（2026-09-24 00:30，Hikari）

WorkingPlan 里那把"C32 产出端 out 字节写并宽"的刀。做法：FFN 收缩、prefix 矩阵、投影三处 WMMA 换操作数顺序（精确转置，同折叠 FFN / mh_fast 尾段），每 lane 持一个 token 行的 8 个连续通道，于是 ffn8 字节写 16→2（8 字节）、scratch.ex 半精度写 16→2（16 字节）、raw FP8 out 字节写 16→2、pre16 同理；残差初始化改读 8 个连续 in16 半精度；投影缩放从 2 个提升读变 16 个。生产开关 0 时 ISA 与 prod6 逐行零差异。

kernel 后缀 ABBA 宿主（c32-lds-alias/network.exe，三个相同的转置孪生 _pair1/2/3 与生产核交错，每槽 1600 次调用，整网逐位检查）：

读法：写指令是少了，但 (a) 转置后残差初始化和 saved_ffn/pw 的访问变成"lane = 行"，in16 读 8 个半精度按 68 字节行距跨 lane 走，LDS bank 冲突比原来按 lane 连续的读差；(b) 投影缩放 2 读→16 读；(c) chain/finish 的 VGPR 升 15 个。三笔抵掉并宽的收益还倒贴。和账本规则一致："转置并宽只对 unrolled 窄写有效，且要看该核当下被什么卡"——C32 卡在读队列，写并宽不是它的瓶颈。
