# 按固定尺寸/编译调度思路扫描全网

基线2f4c8fa；审计当前默认900P路径234次调用，见工具目录audit.md。C32和C64～C256主要矩阵维度本已固定；C512 split矩阵也已固定。本轮没有对这些核统一强制unroll。对仍含动态维度/通道/token的八组分别做保持算术顺序的实验。

## 初筛：每组单独替换

900/1080各4槽ABBA，每槽40预热+100计时，输出逐位比较。数字是候选相对同组基线的整网毫秒差，负数较快；不是各组贡献可相加的固定预算。

| 候选 | 900差值ms | 1080差值ms | 处理 |
|---|---:|---:|---|
| ViT FFN展开，K1024/N4096 | -0.062110 | -0.215190 | 采用 |
| ViT注意力后的投影，K1024/N1024 | -0.084480 | -0.059205 | 采用 |
| 解码器五种通道对 | -0.009760 | -0.044815 | 补叠加复测后采用 |
| C32池化投影 | -0.011730 | +0.013590 | 未采用，两档不一致 |
| C512注意力 | -0.015355 | -0.016115 | 小收益研究候选，未纳入本次组合 |
| C512位移/池化 | -0.009145 | -0.026705 | 小收益研究候选，未纳入本次组合 |
| ViT注意力固定token | +0.004230 | -0.015055 | 未采用，两档不一致 |
| ViT QKV固定token | +0.005240 | -0.055245 | 1080有线索，900无明确收益，未采用 |

全部64槽原始FP32同；每槽验证实际替换数。四实验模块双架构编译，仅gfx1201实跑。其余细微正值没有直接宣布无效，也没有未经复测全部合入。

## 解码器的叠加对照

以已含前两项的mask3为基线，对比mask7，每槽400帧、两档共8槽。900再省约0.019626ms，1080再省约0.043320ms，8槽原始FP32全同。最终保留ViT展开、ViT投影、解码器投影三类改动，每帧影响8+8+5=21次调用。

实现只把已知模型维度送进内联函数；固定的是通道数，图像宽高仍动态处理；通用通道尺寸走原fallback，外部导出签名不变。精度、K累加/分段顺序、舍入和残差都保留。没有增加有损开关。

## 正常入口的最终回归

正常ABI模块同时构建packed/unpacked、gfx1200/gfx1201。其余模块来自mh-empty-c256当前基线。真实冻结HDR输入经D3D编码，分别900/1080各千帧ABBA，去每槽前200帧后统计：

| 档位 | 基线ms | 三项合并ms | 省ms | 降低 |
|---|---:|---:|---:|---:|
| 900 | 13.158996 | 12.999306 | 0.159690 | 1.21% |
| 1080 | 18.607489 | 18.297279 | 0.310209 | 1.67% |

计时合计8000帧，耗时数值有限；计时模式只检查首尾帧的像素统计（均有限），各槽最终输出黄金值一致。900/1080静止/平移，加720平移、900历史、float输入、float feature，共96对逐帧RGB完全相同。短12帧控制用于正确性，启动/预热波动大，不把其均值作性能判断。另在最终正常ABI模块上做900/1080各两次原始网络FP32核对。

这是一轮默认路径全网筛选，采用范围是三类算子；不是所有可选路径/每个内部循环都已优化完。生产改动在hip/deep_fast.hip，游戏部署及发布包不在本轮范围。gfx1200只编译，未实机运行。

## 学到的机制

固定模型尺寸可以让编译器提前安排更多读取、消去动态地址计算、改变展开策略，上一轮ViT正反实验已给出因果证据。但其他核本来就用常量，或主要成本不在这一段，因此不能期待“全网固定尺寸”按同一比例提速。是否采用仍看最终组合的整网计时和输出。

初扫CSV/遥测、叠加对照、回归CSV/逐帧hash、两架构模块hash分别保留；sweep-summary.json和regression-summary.json可由analyze.py重建。最终source与已编译selected-source逐字相同。
