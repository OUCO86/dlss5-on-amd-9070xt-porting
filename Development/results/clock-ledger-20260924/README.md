# 频率账本：这张卡在网络里为什么跑 2.75 GHz 而不是 3.1（2026-09-24 01:00，Hikari）

318 第一章留了个问题：峰值测试 3.1 GHz，整网 2.74～2.79，ViT 单测 2.5，没追问为什么。这里用"让一个核族占满一帧"的办法逐族量时钟和功耗：`DLSS5_HIP_DUP_PREFIX` + `DLSS5_HIP_DUP_COUNT=8`（flags 文件里，纯函数核重放 8 次输出不变），每个配置 400 帧，ADL 200ms 遥测只取 GFX 活动 ≥90% 的样本、去掉前四分之一。宿主 benchmark_clock_observe.exe，prod6 模块，network-timeline 的生产 flags，输入 live-menu-before.f16。第一遍误把开关放在环境变量里，等于跑了六遍基线，顺手当成了重复性数据（data/ 下 900-/1080-base 系列之外的六个目录）。

## 读法

1. **板功耗在每个配置都钉在 325～328 W。** 不管哪个核族占满一帧，功耗不动，动的是时钟。这就是功耗墙：卡按功耗上限调频，跑什么决定能跑多快。峰值测试那次 330 W 却有 3.1 GHz，是因为纯寄存器矩阵每个周期耗的电少；网络里的显存、LDS、栅栏每个周期更费电，同样的电只够 2.75。
2. **最费电的是 C64～C256 的 FFN 核**：它占满一帧时时钟掉到 2.51～2.55 GHz，比基线低 8～9%。C32 占满时低 1～1.5%。C512 和 C256 注意力与基线持平。
3. **ViT 反而是最省电的**：占满时时钟 2.78～2.85，比基线还高 1～2%。318 里"ViT 单测只有 2.5 GHz"是孤立微基准下的读数（那些实验显存档位在 1538/2238 之间跳），不是它在整网里的状态；那句话要改。
4. 整网 2.75 就是这几族按时间加权的结果。功耗墙下"少发指令"的收益在同批 ABBA 里已经体现（每槽 20 秒足够调频稳定），所以旧 null 不用因此翻案；但它指出一条新的杠杆：**让 FFN 核族更省电，全帧的时钟都会抬**。上界估计：FFN 占 1080 一帧 3.8/17 ≈ 22%，若它的功耗降到 ViT 那一档，整网时钟约从 2.75 抬到 2.78～2.80，1～2%。
5. 用户侧：功耗上限是这张卡的第一约束。论坛报告把功耗上限从 340 提到 350+ 帧率涨 2～3，和这里一致；Adrenalin 里 +10% 功耗上限值得在剑星里实测一次（本实验没改任何调校）。

## 边界

ADL 200ms 粗采样，节流原因传感器不支持，"功耗墙"是从"功耗不变、时钟随负载变"推的，不是读到的节流标志。边际成本按 (dup8 − base)/7，重放的核缓存是热的，略低于区段 ABBA 的数。工具 `Development/HIP/experiments/clock-ledger`（run.ps1 / analyze.py）。
