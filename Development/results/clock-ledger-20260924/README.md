# 频率账本：这张卡在网络里为什么跑 2.75 GHz 而不是 3.1（2026-09-24 01:00，Hikari）

318 第一章留了个问题：峰值测试 3.1 GHz，整网 2.74～2.79，ViT 单测 2.5，没追问为什么。这里用"让一个核族占满一帧"的办法逐族量时钟和功耗：`DLSS5_HIP_DUP_PREFIX` + `DLSS5_HIP_DUP_COUNT=8`（flags 文件里，纯函数核重放 8 次输出不变），每个配置 400 帧，ADL 200ms 遥测只取 GFX 活动 ≥90% 的样本、去掉前四分之一。宿主 benchmark_clock_observe.exe，prod6 模块，network-timeline 的生产 flags，输入 live-menu-before.f16。第一遍误把开关放在环境变量里，等于跑了六遍基线，顺手当成了重复性数据（data/ 下 900-/1080-base 系列之外的六个目录）。

## 读法

1. **板功耗在每个配置都钉在 325～328 W。** 不管哪个核族占满一帧，功耗不动，动的是时钟。这就是功耗墙：卡按功耗上限调频，跑什么决定能跑多快。峰值测试那次 330 W 却有 3.1 GHz，是因为纯寄存器矩阵每个周期耗的电少；网络里的显存、LDS、栅栏每个周期更费电，同样的电只够 2.75。
2. **最费电的是 C64～C256 的 FFN 核**：它占满一帧时时钟掉到 2.51～2.55 GHz，比基线低 8～9%。C32 占满时低 1～1.5%。C512 和 C256 注意力与基线持平。
3. **ViT 反而是最省电的**：占满时时钟 2.78～2.85，比基线还高 1～2%。318 里"ViT 单测只有 2.5 GHz"是孤立微基准下的读数（那些实验显存档位在 1538/2238 之间跳），不是它在整网里的状态；那句话要改。
4. 整网 2.75 就是这几族按时间加权的结果。功耗墙下"少发指令"的收益在同批 ABBA 里已经体现（每槽 20 秒足够调频稳定），所以旧 null 不用因此翻案；但它指出一条新的杠杆：**让 FFN 核族更省电，全帧的时钟都会抬**。上界估计：FFN 占 1080 一帧 3.8/17 ≈ 22%，若它的功耗降到 ViT 那一档，整网时钟约从 2.75 抬到 2.78～2.80，1～2%。
5. 用户侧：功耗上限是这张卡的第一约束。论坛报告把功耗上限从 340 提到 350+ 帧率涨 2～3，和这里一致；Adrenalin 里 +10% 功耗上限值得在剑星里实测一次（本实验没改任何调校）。

## 边界

ADL 200ms 粗采样，节流原因传感器不支持，"功耗墙"是从"功耗不变、时钟随负载变"推的，不是读到的节流标志。边际成本按 (dup8 − base)/7，重放的核缓存是热的，略低于区段 ABBA 的数。工具 `Development/HIP/experiments/clock-ledger`（run.ps1 / analyze.py）。

## 追问：FFN 核族的电烧在哪（01:10～01:15，ffn-tail/ 与 ffn-stores/）

同一方法，让 `mh_ffn_fused_c*` 占满一帧（dup×8，1080，400 帧），换 mh_fast 模块看时钟。板功耗全程 327～328 W。

第一轮（prod5 时代的核 + mhfast-tail-ablate 的三把尾段消融）：

| mh_fast 模块 | 帧 ms | 核心 MHz |
|---|---:|---:|
| prod5 未消融（两次） | 45.7 / 46.1 | 2556 / 2536 |
| pair1 串行平方和 → 1 次平方 | 45.1 | 2542 |
| pair2 去掉归一化交换（storage.raw、2 barrier、inverse） | 43.7 | 2534 |
| pair3 24 条 norm 单字节写永不执行 | 43.1 | **2661** |

第二轮（prod6 = 转置尾段，norm 写已从每 lane 24 条 b8 并成 3 条 b64；新消融 prepare-power.py）：

| mh_fast 模块 | 帧 ms | 核心 MHz |
|---|---:|---:|
| prod5（两次） | 46.0 / 46.2 | 2546 / 2532 |
| prod6（两次） | 43.3 / 43.7 | 2528 / 2509 |
| pair4 prod6 去 norm 写 | 40.4 | **2625** |
| pair5 prod6 去 out 写 | 42.8 | 2540 |
| pair6 prod6 两者都去 | 42.2 | **2700** |

读法：

- ALU（串行求和）和 LDS 交换 + barrier 都不耗电（pair1/pair2 时钟不动）。**耗电的是全局窄写**：去掉 norm 写 +4%，两路写都去 +7%（两者相加不止 4.5%，写流量低到某个程度以下省得更多）。
- **并宽指令数不省电**：prod6 把 norm 写从 24 条并成 3 条，时间 −2.6ms 但时钟一点没抬（2528 对 2546）。转置后 lane = 行，每条写指令 32 个 lane 落 16 条不同的缓存行，触及的行数和原来一样——**功耗跟着"触及的缓存行数 × 部分写"走，不跟指令数走**。这和 318 那条"读写成本 = 指令数 + 触及行数"是同一件事的功耗面。
- 上界：FFN 核族占 1080 一帧约 22%，两路写在核族内值 7% 时钟，折到整帧约 1.5%；再加上少请求本身的时间收益（pair6 帧 −2.6%）。

## 由此定的下一把刀：FFN 尾段的全行写（逐位）

out 的字节其实已经在 LDS 里了（qfeature 就是 [16 行][C+4] 的暂存，后面还有一个现成的 barrier）；一个工作组的 out 是 16×C 字节连续的一整块（C=256 时 4 KB）。改成 barrier 之后由全组从 qfeature 按 8 字节/线程写出：一个 wave 写 256 B 连续 = 两条整行，每行只被写一次，不再是 4～8 次部分写。norm 同理：按 part 暂存 16×C 字节到一块 4 KB 的 LDS，在下一 part 的第一个 barrier 之后整行写出（流水，不加 barrier，最后一 part 多一次），每行 C 字节 = 两条整行。LDS 每组 +4 KB（21.5→25.5 KB，WGP 模式 128 KB 仍放 5 组，驻留由 VGPR 定不受影响）。同字节同地址 → 逐位。预期：FFN 占满时时钟回升接近 pair6 的 7%，整帧 1～2%，加请求数下降的时间收益。明天做。
