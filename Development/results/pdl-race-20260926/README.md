# 生产基线 900 历史偶发不一致：复现与 PDL 协议审计（2026-09-26）

起因：c512-ffn 回归（17a9510）中，现行生产（prod8 + wave-owned + PDL=1，C512_M32=0）的 900 连续历史用例有一次第 8～11 帧与其余运行不同，复跑 20+ 次未再现。嫌疑 PDL 土法旗子。

## 1. 先纠正参考

回归里的 `extra-900-history-False` **本身就是那次异常**：它的第 8～11 帧与另外 20 多次运行（含 PDL=0）都不同；多数一致的结果（frame 8 哈希 `F9FABBE4…`）才是正确参考，本轮以 `flaky2-pdl1\b1` 为 900 参考。

异常的形态（`rgb-frame-8` 对比）：第 0～7 帧逐位相同；第 8 帧整幅都有微差（亮度均值 1e-6 量级，最大 0.10），热点集中在网络坐标 x≈770～1340 的一条纵带（25 列 64px 格中的第 12～20 列、全部行）；第 9～11 帧是历史把误差带下去。那次运行的帧时明显抖动（帧 3/6/8/11 为 18/18/23/23ms，正常约 12～17ms），说明当时 GPU 上有外部负载。

## 2. 复现（全部 0 次）

| 实验 | 配置 | 次数 | 不一致 |
|---|---|---:|---:|
| 900 历史重复 | PDL=1 / PDL=0 | 50 / 50 | 0 / 0 |
| 900 历史 + 同时跑 1080 计时回放作干扰（受害帧时 24～27ms，比异常那次更重） | PDL=1 / PDL=0 | 60 / 60 | 0 / 0 |
| 按回归原顺序：先跑 720 运动候选（C512_M32=1）进程，紧接 900 历史基线 | PDL=1 | 30 | 0 |
| 1080 历史重复 | PDL=1 | 50 | 0 |

合计 PDL=1 190 次（900）+ 50 次（1080）、PDL=0 110 次，零不一致。**不能定性为 PDL 竞态**，也没有复现到任何配置下的失败。

## 3. 协议审计（生产 `Development/HIP/hip_reference_network.h`、`hip/multihead_fast_padded.hip`、`hip/wave_owned_attention_*.inc`）

wave-owned 下 PDL 只作用于 C256 链（C64/C128 整块核是普通带 barrier 的提交，并把 `pdl_prev` 清空）：
- **RAW**：FFN_pdl 组等上一块 attention 覆盖其 16 个 token 的窗口计数器（按上一块 shift/padded 网格换算）；c256_attn_wave 等本窗口 64 个 token 所在的 FFN 组计数器（p/16）。依赖是空间局部的，传递链成立。
- **发布**：每个 wave 在自己的写之后 `fence(release, agent)` 再 +1；目标为累计 wave 数（FFN 16/组，wave-owned attention 8/窗口），计数器按（kind, c, 网格宽高）分槽、永不清零，主机端累计目标与内核实际增量一致。
- **WAR / 池回收**：`Body` 尾部把 input/ffn/producer_norm/out 放进 `pdl_keep`（保留 32 个 ≈ 8 块），C256 链最长 7 块，链内不会回收在途张量；链头是普通提交，隔离了更早的读者。
- **缓存可见性**：消费端没有 per-group acquire，依赖派发包自带的 acquire（启动时失效 L0/GL1）。成立的前提是被读的缓存行不跨两个完成时间不同的 tile；C256 字节特征 256B/token、归一化 QKV 768B/token，行对齐，未发现跨 tile 共享行。

审计**没有找到能解释那次异常的具体缺陷**。一条仍是理论空档：若将来有核读取跨 tile 的非对齐行（窄通道、f16 半行），无 acquire 的方案会失效，届时需要在等待后补 `buffer_gl0_inv/gl1_inv`。

## 4. PDL 的性能价值（现行生产，千帧，去前 200，3 轮 ABBA）

| 档 | PDL=1 | PDL=0 | 差 |
|---|---:|---:|---:|
| 900 | 11.156 ms | 11.237 ms | −0.081 ms（−0.72%） |
| 1080 | 15.701 ms | 15.772 ms | −0.071 ms（−0.45%） |

wave-owned 接管 C64/C128 之后，PDL 只剩 C256 链，收益从 09-25 的 −1.6% 缩到约 −0.5～−0.7%。

## 结论与建议

- 复现率：PDL=1 0/240，PDL=0 0/110（含干扰与原进程顺序）。根因未定；证据不支持"PDL 竞态"，异常伴随明显外部 GPU 负载，纵带状热点更像低分辨率层（C512/ViT 量级的格子）一次性出错，也不排除驱动/硬件瞬态。
- **不调整默认值**，生产保持 PDL=1。若游戏里或回归中再出现，兜底改 PDL=0 只多约 0.07～0.08 ms/帧。
- 以后回归遇到单次不一致：先保存该次全部帧、run.log 与当时的进程列表，再与多数结果比，不要默认把第一次运行当参考。
