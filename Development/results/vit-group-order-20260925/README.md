# ViT 局部二维工作组顺序：展开/收缩六个候选均无可用收益

2026-09-25 22:33 起，Yami，gfx1201 / prod8。六个候选在 900、1080 档各跑三组整网 ABBA；RGB 槽首尾逐位检查全同。**没有稳定提速，全部不采用。** 生产代码、游戏安装与发布包未改。

## 对照内容

每个工作组仍是一个 wave，输出仍为 16 token × 64 列。原编号优先在同一 token tile 上走完全部输出列；候选让 2/4/8 个 token tile 接连使用同一列权重，试图提高 B 的局部复用。

展开核有 64 个列 tile，收缩核有 16 个；分别修改，未合并两个 null 候选。每个累加器的 K 顺序、输出地址、总工作组数和每组线程数不变。工作组编号不等于物理执行顺序。

这与旧实验的随机 stride 置换、多 wave 合组不同；借鉴的是 FlashAttention PR #2217 的复用思想，不是直接移植长序列按头分组的实现。

## 数值与机器码核对

- 映射穷举 26,973 个 tile，覆盖各种整组和尾组。900 的 25 行 tile 特别检查最后不足 2/4/8 行的尾组，无漏无重。
- 底包 prod8，host 选项取自当前生产源；强制 PDL=1，adaptive/graph/dup 关，固定真实输入、无 history。
- 每槽预热20、计时160帧，槽首尾读回 RGB 对 expected.f32，全部 bitdiff=0；计时段无读回、无逐核事件。
- 第一轮统计 expand 每帧8次（CSV `expand_calls`）；第二轮统计 expand+contract 每帧16次（`target_calls`），全部命中，避免假 null。
- 两次模块的全部 76 个原核函数体与 prod8 ELF 逐字节一致；同体异名的展开/收缩 control 也与原核逐字节一致。
- 展开原核 VGPR=77，GM2=78，GM4/8=77；收缩原核205，GM2=211、GM4/8=212。读取指令的静态条数未变，但代码大小和调度改变，不能把耗时差全部归给缓存。

这是固定输入候选筛选，不替代多帧历史回归；候选不采用，故不做双架构发布验证。实验只能说明这六种真实实现没有可用整网收益，不能证明所有缓存调度方式都无效。
