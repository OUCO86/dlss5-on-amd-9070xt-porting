# ffn_fused 尾段转置：投影/QKV 的 WMMA 操作数对调，逐位同，−0.28/−0.21ms（2026-09-23，Hikari）

起点：[尾段消融](../mhfast-tail-ablate-20260923/README.md)给出归一化交换 1.8%、norm 输出写 1～2% 的上界。这一步先做逐位能保住的部分。

改法（`mh_ffn_qkv_body` 的 Project 非 BatchNorm 路径，7 处）：投影 `result=wmma(a,b)` 与 QKV `q=wmma(a,b)` 改为 `wmma(b,a)`——A/B 片段寄存器布局相同（C32 折叠 FFN、mh 注意力已验证），得到的是转置结果：lane 持一个 token 行、8 个连续列。随之转置索引：残差输入读（8 列连续）、残差缩放 `rs[8]`、out/qfeature 写、storage.raw 行写、`inverse` 读（每 lane 一个值）、norm 写。**串行 32 项平方和不动**，值与顺序全同。pair1 只换索引，pair2 加显式 8 字节 memcpy，pair3 = pair1。

ISA（gfx1201）：

| 核 | 指令 | 全局写 | b8 写 | b64 写 | VGPR |
|---|---:|---:|---:|---:|---:|
| c256 frag mapped bytein 原版 | 2207 | 38 | 86 | 0 | 102 |
| c256 转置 | **1995** | **10** | 46 | 4 | 101 |
| c128 原版 → 转置 | 1832 → 1578 | 38 → 10 | | | 109 → 110 |
| c64 原版 → 转置 | 1616 → 1391 | 32 → 4 | | | 97 → **96** |

编译器自己把 8 个连续字节写并成 b64；pair2 的显式 memcpy 只多了搬运指令，存储数相同。

## 整网 ABBA（模块集 host，每测试 8 槽 160 帧，bitdiff 0）

| 档 | pair1 | pair2 | pair3 | 槽不交叠 |
|---|---:|---:|---:|---|

核心频率两侧相同（2737 / 2754 MHz 中位）。基线 prod5。

## 读法

- 比事前估的 ≤0.1ms 大三倍。按"请求 = 指令 × 触及缓存行"算，全局写触及的行数前后一样（24 条 b8 × 2 行 = 3 条 b64 × 16 行 = 48），所以那条规则**不完整**：指令条数本身也是成本（发射槽、存储队列项），C512 split_projection 那次变差是因为并宽后每条指令触及的行数从 1 涨到 32，行数项压过了指令项。修正后的说法：**读写成本 ≈ 指令数 + 触及行数，两项都要看；并宽只在行数不涨（或涨得少）时净赚。**
- 消融给的"norm 输出写"上界 1～2% 这次拿回了大半；"归一化交换"1.8% 里 LDS 往返那部分也顺手拿了一点（storage.raw 写 8 → 编译器合并后更少）。剩下的是两个 barrier 和串行求和本身（消融 0.7%），那才是非逐位的部分。
