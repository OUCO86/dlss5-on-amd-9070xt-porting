# 真正网络时序中的ViT区域，以及短段计时的边界

2026-09-22。对照生产路径与上一轮32×64/片段A/u2候选，每帧替换8次pack+8次expand，使用既有gfx1201模块与冻结输入。Graph/自适应复用/历史关闭。没有改GPU频率、生产代码或游戏包。

## 1. 单个pack+expand直接事件计时拒收

在block31的pack前与expand后各记录HIP事件；每计时帧独立事件对象，同一stream。160帧后读数发现非正间隔；保留三次过程：

- 初版等待stream完成后批量读取，遇非正值即中止，没有保留具体异常原值（rejected-before-event-sync）。
- 加入结束事件同步后，160笔中59笔非正，min −0.019980ms、max0.075500ms，平均0.008499ms（rejected-batched-event-sync）。
- 改为每帧立即同步起止事件并读取，仍有61/160笔非正，平均0.010970ms（rejected-immediate）。

这些不能作为真实算子耗时，不删负值、不裁0、不继续平均后宣称收益。事件每帧不同，立即读取仍失败，排除了“仅由批量延迟读取造成”的简单解释。当前不能确定是HIP计时实现还是插桩方式导致；不据此否定之前正常整网wall测量，也不直接断言显卡有硬件缺陷。

## 2. 长前缀差分：有效长时段，短差值噪声仍大

使用之前验证的长前缀结构：网络开始→目标边界→网络结束三个事件。目标边界在block31 pack之前或expand之后，每四帧ABBA切边界。每个形状/模式64组四帧差分；原核/候选外层再按两轮ABBA交错。全部1024标记帧的prefix/whole/tail为正，prefix+tail≈whole且whole不超过CPU wall容限。

| 档位/模式 |平均差分μs|逐轮差分标准差μs|
|---|---:|---:|
|1080原核|70.530|81.888|
|1080候选|63.830|148.428|
|900原核|75.420|48.381|
|900候选|59.448|51.506|

两个数毫秒前缀相减来估几十微秒段，仍受前序帧间波动影响。不能拿这些均值定论候选快6.7/16μs，更不能把其与热核wall的差值全归缓存。保留所有正负差分（差分估计为负与上一节事件本身负时长是两种情况）。每槽前后各80帧无标记control，原始FP32检查通过。

## 3. 放大到整个ViT区间，得到稳定正时长

改为第一次pack前→block38 Stage后，只用一对事件覆盖八个ViT块。读取在每帧GPU完成之后，区间内不加CPU同步/回读。四组各两轮ABBA：无标记原核/候选、两边都标记、仅原核标记开关、仅候选标记开关。每槽30预热+160计时。

| 配对 |1080原核→候选|900原核→候选|
|---|---:|---:|
|无标记整网wall ms|17.869095→17.865163|12.796713→12.815408|
|有标记整网wall ms|18.056948→18.051102|12.929003→12.910111|
|标记的ViT区间GPU ms|2.051730→2.051415|1.272712→1.268393|

5120笔区域事件读数全部有限且为正。1080区域变化约0.3μs；900约4.3μs，均未重现热微段8～16%的幅度。该区域包含FFN、attention等其他运算，不能把区域百分比与单个展开算子百分比直接相比；小收益被稀释、频率/缓存/调度环境变化仍未完全分开。

明确量到插桩代价：

| 标记开关控制 |无标记wall ms|标记+逐帧读取wall ms|增加ms|
|---|---:|---:|---:|
|1080原核|18.109703|18.179920|0.070217|
|1080候选|18.087716|18.178698|0.090983|
|900原核|12.868211|12.958653|0.090442|
|900候选|12.851347|12.928014|0.076667|

这包含事件插入、完成/读取API与可能的调度变化，不全是GPU事件执行时间。增加0.39～0.70%，比候选整网差异还大，不能把标记版wall当原版性能。前缀/区域事件也不是逐周期缓存等待或矩阵利用率测量。

## 结论与范围

没有形成采用新tile的证据，生产保持原版。本轮推进是确定测量尺度：当前短段直接事件方法无效；长前缀对几十微秒差分仍不够精细；放大区间能看趋势，但须承认标记/读数的成本与其他ViT工作的稀释。

接受的前缀试验16槽、3584计时帧、48次完整原始FP32检查；区域试验64槽、10240计时帧、64次完整FP32检查。合计112次全同，候选替换计数符合每帧16次。失败的短段轮次另留目录，不混入接受数据。

下一步优先用无短段事件的放大对照：在真实网络中对选定pack+expand增加受控重复，保持原输出，再比较重复次数的整网wall增量及候选差异；必须将额外重复造成的缓存/并行变化单列，不能把边际增量叫作原生算子耗时，也不能当生产加速。仍未解释完算力缺口。
