# C512 split_projection_frag 转置尾声：逐位同，略差，不采用（2026-09-23，Hikari）

想法：该核每 lane 64 条标量写（32 f32 + 32 字节）+ 36 条标量残差读，累加器只喂尾声。对调 WMMA 操作数让每 lane 持一行 8 个连续列，写并成 b128×2 + b64、残差读并成 b128。逐位同。

结果：整网 1080 −0.023 / +0.018 / +0.021ms，900 +0.024 / +0.014 / +0.027，交叠、偏差。

**反例的教训**：原布局下同一条标量写指令里 16 个 lane 写的是连续 64 字节（lane=列），跨 lane 已经合并成少量缓存行；转置后每条向量写指令 32 个 lane 各落一行（行距 2KB），一条指令触及 32 条行。**内存管线的"请求"按"指令 × 触及的缓存行数"计，不按指令条数。** 昨晚 C32 staging 并宽能赚，是因为并宽后 lane 之间仍然连续（32 lane × 16B = 512B 一段）。同理，split_ffn / split_mix / vit_project 的标量写也不该转置。

证据：r1/。工具 HIP/experiments/deep-transposed-epilogue。
