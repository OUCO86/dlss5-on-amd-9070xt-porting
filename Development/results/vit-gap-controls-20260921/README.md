# 改善后ViT展开的剩余算力缺口：调度对照与运行状态

基线70656f8（已采用固定尺寸展开/投影/解码器）。真实block31输入权重，M400/640、K1024/N4096，两个诊断架构均编译，实跑gfx1201。目的为解释缺口，本轮没有生产改动。

## 三类对照与稳定的1080结果

保持每个结果的K累加顺序、输入、权重、激活/FP8输出不变；原导出与每候选两轮ABBA，每槽约50ms预热/200ms批计时。每槽先用参考结果逐字节取反填满输出，再检查全部产出，避免漏写沿用旧值。host wall+stream sync，无密集逐核事件。

全部无scratch。u1/2/4/8/16的VGPR47/57/77/94/97。运行时API给原核、u1～u8、group4/8、双行tile均64wave/MP驻留上限，u16为56；这是上限，非实际活跃wave计数。单wave工作组并未被API报告为只能驻留很少wave，合组也没带来明显1080提速，因此“只因工作组太小、组数上限卡住”缺少支持。

每个结果仍只有原来的4条独立累加链，增加K展开不增加独立结果数。双行tile增加累加链和权重重用，也减少工作组数、改变寄存器/调度，不能因它变慢就排除访存或并行度问题。列优先也改变地址计算/缓存访问顺序，不能当成缓存命中率实测。当前数据只说明这些具体安排没填上缺口。

## 900初扫不能作候选排名

同一个原核在不同槽出现约26～44μs，初扫显存时钟读数常在约180～650MHz低档；1080大部分计时则为2238MHz且基线约36μs稳定。900个别候选表面快十几至二十个百分点，与基线漂移混在一起，不采纳其排名。

另启进程按1080→900顺序，只复测原核与显式u4。1080仍约35～36μs、显存2238MHz；900仍约28～37μs、显存读数约220～260MHz。排除了“只有初扫开头偶发一下”的解释，但没有证明驱动选择低档的内部原因。

## 相同代码、改变计时前负载的正反对照

新增同核ABBA：A在计时前连续运行原核约200ms；B改为两个128MiB设备缓冲之间反复D2D复制约200ms。此后两者都按同样方法预热约50ms、计时约200ms，测的始终是原核。复制不进入计时区间，输出完全相同。

| 档位 | 原核预热后μs | 搬运预热后μs | 核心MHz中位 A→B | 显存MHz中位 A→B |
|---|---:|---:|---:|---:|
| 900 | 36.651 | 26.997 | 2859→3143.5 | 257→2505 |
| 1080 | 36.232 | 35.212 | 2499.5→2801.5 | 2238→2475.5 |

900 A四槽27.76/40.67/39.43/38.74，B为26.27/27.37/27.32/27.03，B明显更集中。说明相同核、相同输入的速度会受前序负载及运行状态影响，不能把短测差值都归给源码。900的A基线仍不稳定，-26.34%只能描述这组均值差，不作为稳定提速率。

这不是纯显存频率干预：核心时钟、缓存状态和其他功耗状态也可能一起改变；200ms ADL粗采样，每个方向只有2～4个配对采样点，还可能有指标更新滞后。不能因此给显存等待算精确占比，也不宣称找到了驱动bug。全程没有更改频率/功耗/电压/风扇。额外搬运成本远高于省下的微秒，只是诊断，不是优化方案。

## 校正148与405的比较口径

稳定1080的u4对照，原核36.386μs，对应主矩阵147.55TF；核心配对中位2460MHz。按同一硬件计数口径64×2048×核心MHz/1e6，参考上限约322.44TF。另一个稳定基线2499.5MHz对应327.61TF。

原405.28TF寄存器峰值是在约3114MHz观察到的。真实核运行条件不同，所以直接用148/405当利用率不合适。校正频率后，这个真实工作负载的主矩阵吞吐仍约为粗略时钟参考的45～46%。这依然不是硬件利用率计数器：分母是频率参考，分子只计主矩阵且总耗时含读取/激活/写出。时钟差只校正比较口径，不等于解释了各环节耗时。

## 当前认识与下一轮

已经支持：短循环调度确有损失；当前4份展开附近，再加展开或简单合组没有明显1080收益；真实负载的运行频率低于寄存器峰值测试；900独立热核测试对前序负载/自动运行状态敏感。

仍未知：当前1080约148到约322～328的差距，多少来自单次工作规模/填充收尾、依赖链、读指令吞吐及缓存供数。下一步优先同一launch里复制独立工作、每份输出独立校验，观察单位工作耗时是否随并行工作量下降；再与双行tile/累加链变化交叉，区分重用收益与工作组数量减少的代价。复制工作会改变输出量和缓存占用，须保留单份控制并记录时钟，不能把它直接当单帧优化。

初扫160槽、复测16槽、前序负载16槽，共192槽完整输出逐位同，六进程首尾共12次原始FP32整网同。CSV、遥测、资源/驻留上限、工件hash保留。900初扫的数据仍在，但明确不用于候选排名；本轮没有改游戏、生产推理或发布包。
