# ViT平衡tile：少20%逻辑加载却更慢，A布局能消除这项惩罚

2026-09-22，RX9070XT/gfx1201。接续计算密度探针：将额外矩阵工作换成真实输出重用。生产核基线cdfd6b6，真实block31展开M400/640、K1024、N4096。当前生产/游戏/0.28发布包不改。

## 1. 同样四个累加片段，先改16×64为32×32

1080时wave数量同为2560，主矩阵工作5.36870912 GFLOP不变；每K16的A1+B4改成A2+B2，逻辑加载1280→1024字节，名义密度25.6→32 FLOPs/逻辑字节。900的M400末16行使用BM1独立模板，只计算/存储有效行；wave数1600→1664，实际矩阵工作不变。

每变体两轮ABBA（8槽），每槽约100ms预热/400ms计时；输出计时前以参考反码填充，预检和后检全字节比较。原形状固定参数control用来校准探针。

| 形状/调度 | 1080原核→候选μs | 900原核→候选μs |
|---|---:|---:|
| 原形状control |35.940→35.936|25.141→24.923|
|32×32，K四份展开|36.107→48.616|25.017→31.212|
|32×32，不展开|36.327→78.577|25.073→52.487|
|32×32，列优先顺序|36.433→43.446|25.078→30.280|

减少源码/ISA逻辑加载并没有提速。四份展开仍明显优于不展开；列优先略缓解，但仍比原形状慢。

## 2. A、B的相同字节数不代表相同取数形态

A按行存放，每lane读8字节，相邻rc跨1024字节；B已经是连续片段排列。32×32增加了分散A片段，减少的是连续B片段。以同一K16为例，逐条wave载入触及的对齐地址段数量之和：

| 地址段粒度 |16×64行布局|32×32行布局|16×64片段布局|32×32片段布局|
|---|---:|---:|---:|---:|
|32字节|48|48|40|32|
|64字节|32|40|20|16|
|128字节|24|36|10|8|

由源码地址枚举得出，脚本address-segments.py；**它不是硬件事务计数，也不是DRAM/L2流量测量**，不据此认定缓存行大小、实际命中率或带宽占比。它解释了为何总逻辑字节数不能直接预测取数代价。

随后保持32×32/累加顺序，只把A换成已有片段布局，增加CPU独立置换参考验证pack输出。对照如下：

| 配对项目 |1080 μs|900 μs|
|---|---:|---:|
|行布局：16×64→32×32|35.972→48.524|25.146→31.426|
|片段布局：16×64→32×32|34.884→34.258|24.606→24.063|
|32×32：行→片段布局|48.709→34.442|31.301→24.200|
|打包：行→片段布局|2.270→2.697|1.941→2.405|
|打包+矩阵：生产→片段32×32|39.463→37.342|26.469→25.312|

同样矩阵工作，A布局改变让32×32在1080快29.29%、900快22.69%。1080核心中位反而2674→2537MHz，显存同为2238MHz，不能用更高核心频率解释这次改善。布局同时改变地址指令/编译调度，不将29%全当作某一级缓存等待占比。孤立pack测试触发显存低档，只保留实测，不单独作带宽推算。

当A已连续，换形状只再快约1.8～2.2%；没有达到逻辑密度提升25%所暗示的幅度。原核的大缺口仍未消失。

## 3. ISA与驻留上限

| 核 |VGPR|scratch|编译器Occupancy|每个完整K64循环：WMMA / global_load_b64|
|---|---:|---:|---:|---:|
|原核/固定control|77|0|16|16 / 20|
|32×32行/u4|78|0|16|16 / 16|
|32×32行/u1|49|0|16|每K16为4 / 4|
|32×32列优先/u4|69|0|16|16 / 16|
|32×32片段/u4|80|0|16|16 / 16|
|16×64片段|76|0|16|16 / 20|

均LDS0；运行时查询每MP最多64个32线程block/wave（API报告32 MP）。这是容量上限，不是运行中实际活跃率。性能差异没有对应scratch溢出或驻留容量下降。完整与900尾部循环分开列在isa.json/layout-isa.json，尾部只有两组累加片段。

## 4. 整网验证：不采用

将每帧8次pack和8次expand一起替换；两档各8槽、40帧预热+200帧计时，共3200计时帧。每槽结束核对完整原始FP32输出；候选每槽计数3200次替换，基线0。

| 整网 |生产ms|片段32×32 ms|差值ms|
|---|---:|---:|---:|
|900|12.777513|12.786306|+0.008794|
|1080|17.943379|17.940298|−0.003081|

配对核心中位900为2753→2754MHz，1080为2728→2729MHz；显存均2505MHz。差异远小于槽位漂移，未观察到稳定净收益，保留研究，不进生产。不能把热重复微核的1～2μs节省乘调用次数当实际推理收益。

## 验证与证据

- 两批微基准共144槽，预检/后检完整输出均同；4个进程首尾共8次整网原始FP32同。
- 整网16槽、16次完整原始FP32检查同，替换计数正确。
- 两个候选模块均gfx1200/gfx1201编译，仅gfx1201实跑。原始CSV、200ms只读ADL遥测、模块/host/source哈希及资源查询在本目录。
- 生成器、运行与分析脚本在Development/HIP/experiments/vit-balanced-tile。代码不改频率、功耗、风扇。

## 下一步

目前说明的是**块形状和操作数布局的相互作用**，不是整网算力缺口已经全部归因。下一项可比较16×128与32×64：同样八组累加器、同样输出工作量/大致wave数，分别偏向重用分散A或连续B，并交叉A布局。关注发射/地址指令混合与寄存器容量，不再只用FLOPs/逻辑字节预测效果。先做配对及输出校验，只有收益在整网兑现才采用。
